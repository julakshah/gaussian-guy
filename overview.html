Gaussian Guy

Automated 3D Reconstruction and Object Isolation using Gaussian Splatting and a 6 DOF Arm

We integrated control of a WidowX robotic arm with a pipeline for selecting image frame locations, taking and recording images and the corresponding camera coordinates, generating a 3D reconstruction using Gaussian Splatting, and processing the resulting data to extract reconstruction accuracy metrics and a view of the object with extraneous data masked out.

What does this mean?

We combine the tasks of scanning a 3D scene, a physical task, with regenerating the scene and doing postprocessing on it, a software task. In particular, we use a robotic arm with a camera mounted at its end in order to automatically have the robot scan the object with a particular trajectory in space, returning a number of images. We then process those images to assemble a complete 3D scene, using the relatively modern gsplat library to build a high-fidelity reconstruction of our scene using Gaussian distributions in space.

Arm movement

The arm used is a WidowX arm, building on some existing code from a previous project that interfaced with the arm to control its movements via ROS and Python. In the context of this project, the point of the arm is to allow us an automated way to scan an object from multiple angles. We mount a camera in place of the original robot's end effector, moving the arm around the scanned object to view it from different angles.

Frame selection

It's not hard to get a lot of information from a 3D scan --- just take images as fast as possible. However, we're interested in seeing if we can selectively choose a subset of positions to take images from in a way that will maximize our information captured but be processed more quickly by virtue of being a smaller set. To do this, we implemented a trajectory generation algorithm using A-* and discretizing our space as an octree, seeking to resolve unknown voxels in the octree to get more information.

Reconstruction

We reconstruct the 3D scene of the scanned object via Gaussian Splatting, a modern process for fitting large numbers of Gaussian (normal) distributions in space in order to construct a 3D scene. Unlike traditional 3D scenes, we don't generate a triangluar mesh to define the scene --- instead, the scene is composed of a long list of Gaussians, each of which has a center in space, scales along each of its three axes, an orientation, opacity, and color data.

The process of generating, rendering, and optimizing the layout of these Gaussians in space is both computationally expensive, requiring a GPU, as well as conceptually complicated, and for this reason has been the subject of a number of modern papers. For this reason, implementing parts of Gaussian Splatting ourselves would be outside the scope of this project --- instead, we interface with an existing library for Gaussian Splatting, gsplat, which provides an easy interface.

Additionally, we interface with the generated Gaussian splats in two ways:

  • First, we demonstrate as a proof-of-concept the fact that we can directly edit the Gaussians to adapt our scene in specific ways. In particular, we implement a naive method for isolating our object, assuming it is clearly defined and resting on a flat surface, by directly modifying the splats.
  • Second, we implement a method for viewing the accuracy of the 3D scene by viewing the reconstruction from a specific angle and comparing it to a specific input image. While this can be done for the training images, it can also be done for images separated from the training set, used as a form of validation.
