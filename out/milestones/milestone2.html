Milestone 2

During Milestone 2, we largely worked on our separate components of the project without as much direct integration work between the different components. While working through Milestone 2, we also realized there were a few elements of our project we were unclear about, and took the time to clearly describe the different components of our project in an architecture diagram.

Our remaining work consists of finishing up the individual components, integrating our project together, and running the entire pipeline.

Progress

Arm Movement and Planning

We now have inverse kinematics working for our arm, such that we can provide an x,y,z coordinate, get the necessary robot joint angles, and execute that path on the physical arm.

We also have more of the arm's movement planning implemented. In essence, we want to capture more information about our object shape in fewer images, as this runs more quickly and is easier to process. To do this, we represent our object in space using an octree describing the occupancy of our shape, where each voxel is either empty, filled, or unknown. We've then implemented an A* algorithm to locate the nearest point that will add information (resolve more unknown voxels than a set threshold) and return a sequence of "goal" voxel coordinates to navigate to. The idea is to chain goal positions until all unknown voxels (not surrounded by collision) are identified.

The next step is defining an actual trajectory generation and simple obstacle avoidance algorithm --- given a sequence of voxel waypoints, ensure the next waypoint is valid (check for collisions between shape of robot arm, determined via forward kinematics from the inverse kinematics given end effector X,Y,Z) and navigate to it with a given timestamp.

We also record the end effector pose implicitly with every frame captured, and need to save these to a CSV file for use in reconstruction metrics.

Processing and Reconstruction

At the end of the last milestone, we had Gaussian splatting working on a test dataset using the gsplat library, and had tested COLMAP reconstruction. Now, our progress is as follows:

On the preprocessing side, we refined our video process script to allow for us to skip frames, passing a parameter to use in a modulo operator for determining whether to skip a frame or not.

We also quickly tested that our splatting code works effectively on data closer to what the arm camera will record, quickly generating a decent approximation of an e-stop situated on a table:

We also successfully loaded the splats into Python --- they're stored as a PyTorch tensor, and we can fairly easily load them, do operations on them, convert them to or from Numpy arrays if we so desire, and so forth. We can also do any of these modifications, store the results, and visualize the processed splats. As we wanted to investigate the effect of running a clustering algorithm on these clusters, we ran a clustering algorithm (HDBSCAN) on a subset of our processed splats, constructing a 6D array consisting of X,Y,Z, and the R,G,B components of the first spherical harmonic color. We then identified the clusters by stripping the higher spherical harmonic colors and coloring them only according to their cluster ID:

Similarly, we wanted to ensure we could affect the opacity of gaussians. Opacity is encoded without bounds, and is passed through an activation function to map it to between 0 and 1. By passing it through this activation function, performing our adjustment, and reversing the activation function, we can easily modify the opacity. We demonstrated this by masking out points not identified as being part of a cluster during another clustering pass:

We're still running into issues with clustering working effectively, though we haven't yet tested on our e-stop results, which will be closer to the actual 3D scan data we'll operate on. Forcing large cluster sizes works better, but large clusters max out the RAM of the computer. We considered doing some two-stage process where we make small clusters, approximate those clusters with a few points each, and cluster those cluster means, but we haven't yet explored this or alternatives. This was also given the 30k iteration result, which has more Gaussians than the 7k iteration result. Given the performance of our splatted e-stop, which ran for only 7k iterations and took approximately 15 to 20 minutes, we may have better clustering performance on a smaller set of Gaussians, which naturally results from running gsplat for fewer iterations.

Next Steps

  • The next steps we have before the final deliverable date are as follows:

  • Automatically record end effector pose to a file for every frame.

  • Obstacle detection given robot arm profile and forward kinematics for any set of joint angles.

  • Integration of A* waypoints with trajectory executed by arm.

  • Integration of frames recorded by camera with COLMAP -> gsplat -> postprocess/metric pipeline.

  • Generation of metrics (use frames recorded but not trained on as ground truth; compare ground truth frames to reconstruction at the same angle; compute difference as error.)

  • Refining clustering to effectively isolate object from background.
